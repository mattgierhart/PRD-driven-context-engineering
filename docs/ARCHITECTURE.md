# Repository architecture — what lives where, and which layer it belongs to

This repository is two things at once: the **methodology's own product repository** (it runs the method
on itself) and the **template** other products start from. Five layers coexist; the install manifest
(`.claude/install-manifest.yaml`) is the contract between them and `tests/test_distribution.py` enforces it.

| Layer | Where | Who owns it after a fork / install |
|---|---|---|
| **This repository's own product truth** | `README.md`, `PRD.md`, `SoT/` | Replaced by the seeds below — a product never inherits PRD-CE's decisions |
| **Generic downstream seeds** | `README_template.md`, `PRD_template.md`, `SoT_template/`, `epics/*.seed.md`, `docs/*.seed.md`, `.claude/domain-profile.seed.yaml`, `.claude/agents/*/MEMORY.seed.md` | Seeded **once** into product-owned paths (`template_seed`), then never overwritten (`never_touch`) |
| **Methodology runtime** | `.claude/` (skills, hooks, rules, agents, settings, manifest, VERSION), `scripts/` | Installed and **updated** on upgrade (`framework`); some authoring-only entries are excluded from consumer installs (`direct_exclude`) |
| **Generated plugin payload** | `plugins/prd-ce/`, `.claude-plugin/marketplace.json` | Regenerated from `.claude/` by `scripts/package-plugin.sh`; CI fails on drift — never hand-edit |
| **Scratch** | `temp/` (seven stage dirs) | Ephemeral; harvested into `SoT/` at EPIC close |

```text
/
├── README.md · PRD.md · CLAUDE.md          # this repo's dashboard, product authority, agent operating guide
├── README_template.md · PRD_template.md    # generic seeds for a product repo
├── SoT/                                    # this repo's accepted product memory (SoT.*.md + html/ review layer)
├── SoT_template/                           # generic SoT seed (+ html/ review layer)
├── epics/                                  # EPIC template + README (+ .seed twins)
├── docs/                                   # user-facing docs (index.md is the front door) · v2/ planning · maintainer/archive/
│   └── assets/                             # README screenshots (generated by SoT/html/screenshot.py)
├── temp/                                   # scratch, by lifecycle stage
├── scripts/                                # readiness.py + _readiness/, validate-ids.sh, validate-edges.py, asof.py,
│                                           #   install helpers, package-plugin.sh, check-plugin-sync.sh
├── tests/                                  # readiness, graph-contract, and distribution/installer tests (+ fixtures)
├── install.sh · BLUEPRINT.md               # source-run install into an existing repo
├── CHANGELOG.md · MIGRATION.md             # release notes and upgrade checklists (template version in .claude/VERSION)
├── plugins/prd-ce/ · .claude-plugin/       # generated Claude Code plugin payload + marketplace manifest
├── .github/workflows/                      # tests + readiness smoke · plugin-sync · markdown link check
└── .claude/
    ├── skills/                             # 41 stage skills (prd-v01 … prd-v10) + methodology operators (ghm-*) + init, SKILL_TEMPLATE
    ├── hooks/                              # SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / Subagent hooks + HOOK_CONTRACT.md
    ├── rules/                              # eight auto-loaded rule files
    ├── agents/                             # horizon · studio · devlab · metro (AGENT.md + MEMORY.md)
    ├── domain-profile.yaml                 # ID registry + skill taxonomy
    ├── install-manifest.yaml               # the file-class contract above
    ├── settings.json · VERSION             # hook wiring · template version
    └── README.md                           # the installed-runtime tree
```

**Read order** (for humans and agents): `CLAUDE.md` → `README.md` → `PRD.md` → accepted `SoT/` → the active
EPIC (v0.7+ only). **Truth precedence**: `PRD.md` authorizes lifecycle and scope; accepted SoT records hold
durable detail; an approved EPIC narrows execution.

**Agent note**: `.claude/` can be replaced with `.gemini/`, `.codex/`, or any other agent structure, but the
skills, hooks, and agent model here were built with Anthropic's documentation model in mind.

**Changing anything under `.claude/` or a seeded file**: run `bash scripts/package-plugin.sh`, then
`bash scripts/check-plugin-sync.sh`, then `python3 -m pytest tests/ -q`, and commit the regenerated
payload with the change.
