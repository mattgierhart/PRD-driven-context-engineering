BR-001

Product Management Is the Sole V2 Lifecycle

CriticalActive
Category
Methodology Governance
Created / reviewed
2026-08-08
Authority
Owner-confirmed · Wave 0B
Valid
PRD v0.1 → —
Rule
PRD-CE V2 MUST serve the Product Management lifecycle only. Adjacent methodologies MUST remain separately governed and MUST NOT broaden V2 scope.
Rationale

One lifecycle keeps the promise, vocabulary, validation, and first user experience coherent.

Enforcement

Review root PRD scope, lifecycle gates, reusable artifacts, and public claims at every gate and release decision.

Failure disposition

V2_SCOPE_EXPANSION — block advancement or release until the expansion is removed or separately governed.

Relationships

No typed-ID dependency asserted; this rule directly constrains the root PRD.

Evidence & confidence

Build plan §2 · Confidence: 1/5 — normative owner decision; next target is v0.2 audience evidence.

BR-002

Reusable Packages Stay Generic and Non-Destructive

CriticalActive
Category
Patterns
Created / reviewed
2026-08-08
Authority
Owner-confirmed · Wave 0B
Valid
PRD v0.1 → —
Rule
Reusable artifacts MUST stay generic, exclude downstream/private/maintainer material, and MUST NOT overwrite consumer-owned product content.
Rationale

Repository-specific seed truth contaminates downstream products; directory replacement can destroy consumer work.

Enforcement

Manifest, installers, packager, and isolated tests preserve product files, domain profile, memory, and unrelated framework-directory additions.

Failure disposition

DISTRIBUTION_LEAK_OR_OVERWRITE — block packaging and release until isolated proofs pass.

Evidence & confidence

Build plan §2–§3 + passing Wave 0B clean-install, forced-reinstall, plugin-parity, link, package, and sensitive-reference tests · Confidence: 4/5. CI and release-lifecycle evidence remain outstanding.
