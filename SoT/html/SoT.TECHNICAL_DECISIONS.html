ARC-003

First Executable Value Is Read-Only In-Place Inspection

Owner-confirmed · Wave 0B

PRD v0.1 → —

Proposed / not implemented
Context

Migration and mutation multiply risk before compatibility, identity, provenance, time, and divergence behavior are understood.

Decision

The first V2 executable MUST inspect a repository in place, cite exact sources, and leave authored files and Git state unchanged. It excludes migration, writers, Change Set application, MCP, hosted services, V2 runtime/command-provider parity, and root SoT relocation.

Rationale & consequences

One future alpha contract replaces competing first releases: compatibility parsing, typed identity/edges, deterministic validation, a disposable local projection, and read-only index/check/query/trace behavior only after v0.7 approval.

Validation state

The Compatibility Inspector and all V2 commands are Proposed and not implemented. Wave 0B adds no runtime or EPIC.

Relationships

depends-on → ARC-001 · depends-on → ARC-002

Evidence & confidence

Build plan executive direction and Wave 2 · Confidence: 1/5 — next target is a v0.7-authorized non-mutating proof.

ARC-004

Repository Authority and Downstream Seeds Are Separate

PatternsAccepted decision
Decision / review date
2026-08-08
Authority
Owner-confirmed · Wave 0B
Valid
PRD v0.1 → —
Runtime validation
Wave 0B packaging; V2 runtime Proposed
Context

Root PRD and SoT are repository authority, but reusing them as downstream seeds leaks PRD-CE development truth into consumer products.

Decision

Root PRD.md and SoT/ stay repository authority; explicit PRD_template.md and SoT_template/ sources seed canonical consumer destinations once.

Rationale & consequences

Separate paths are mechanically auditable. Direct and plugin-native installation must copy the same generic bytes and preserve existing canonical consumer files.

Validation state

Wave 0B implements the boundary, subject to clean-install, reinstall, parity, link, sync, and sensitive-reference tests. It adds no V2 runtime.
