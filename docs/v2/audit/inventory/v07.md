## Group observations

**These three skills are one thing.** Epic scoping, test planning, and implementation loop are the plan/contract/execute facets of a single `build` verb, and they already share a circulatory system: the EPIC record, the Session State protocol, the Assumptions & Ambiguities table, the @implements grammar, and the "cite IDs or it didn't happen" standard. None of the three is a playbook — a playbook is optional, and nothing here is optional to building. All three should collapse into the `build` kernel behavior, with their checkable criteria extracted into two policy packs for `check` (`test-coverage`, `build-completion`/devgraph-green) and their record schemas (EPIC, TEST-, Session State) moving to the Delivery plane, with the Assumptions & Ambiguities table graduating to the Change plane as its intake format.

**The strongest distilled material is anti-LLM-failure-mode discipline, not process.** The genuinely irreplaceable content is a taxonomy of named AI-coding failure modes with countermeasures: Assumption Drift, Overbuilding, Drive-By Refactoring, Smuggled Assumptions in tests, Vague Completion Claims, Session Amnesia, orphan "future use" code. `references/behavioral-examples.md` is the crown jewel of the group — good/bad code diffs that make each failure auditable through the ID system. This material was written *for* model babysitting but is not model-era scaffolding: bigger models still overbuild, still drive-by refactor, still smuggle unreviewed requirements into tests. Preserve it verbatim as the build kernel's discipline reference.

**Calibration numbers are the second treasure — but should become config.** The group carries a coherent set of experience-derived numbers: 3-5 APIs / 2-4 tables / 1-2 UJs per EPIC, 3-7 EPICs per MVP, >5 SoT files = split signal, 30-50 tests per MVP, 1-happy+1-error per endpoint, 3-concrete-uses before abstracting, 60/30/10 pyramid. The token budgets (100k/200k) are the only era-bound ones; in v2 all of these belong in a kernel config/defaults file, not in prose repeated per skill.

**Consolidation math**: ~3,000 lines across 14 files reduce to roughly one build-kernel doc (loop + guardrails + calibration defaults), one discipline reference (behavioral-examples, extended with test-planning's smuggled-assumptions section and epic-scoping's silent-assignment rule — they are the same failure family), two policy packs, three Delivery-plane record schemas, and one small reference library (dependency patterns, test-type guide). Session State content alone is stated five times today and needs stating once; the duplicate EPIC templates have already drifted from each other (§0 vs §1 numbering), which is the canonical argument for single-sourcing.
